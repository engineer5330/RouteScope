# RouteScope

[![CI](https://github.com/engineer5330/RouteScope/actions/workflows/ci.yml/badge.svg)](https://github.com/engineer5330/RouteScope/actions/workflows/ci.yml)

RouteScope показывает, что произошло при системном разрешении имени, TCP-подключении к полученным адресам и, по желанию, проверенном TLS-рукопожатии. Это небольшой CLI для macOS и Linux на Python 3.11+ без обязательных runtime-зависимостей.

## Установка и запуск

```bash
git clone https://github.com/engineer5330/RouteScope.git
cd RouteScope
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
routescope diagnose localhost --ports 8000 --timeout 2
python -m routescope diagnose 127.0.0.1 --ports 8000 --format json
```

Для диагностики используйте собственные системы или разрешение их владельца. RouteScope не требует root и не отправляет данные приложения после установления TCP-соединения.

## Команда

```text
routescope diagnose HOST [HOST ...] --ports 80,443
    [--family ipv4|ipv6|both] [--timeout SECONDS]
    [--concurrency N] [--format text|json] [--tls]
```

Например:

```bash
routescope diagnose example.com --ports 80,443
routescope diagnose example.com --ports 443 --format json
routescope diagnose localhost 127.0.0.1 --ports 8000 --family ipv4
routescope diagnose example.com --ports 443 --tls --format json
```

`--ports` обязателен. Повторяющиеся узлы и порты удаляются с сохранением первого появления. Семейство по умолчанию — `both`, тайм-аут каждой DNS-, TCP- или TLS-операции — 3 секунды, общий предел параллельных TCP/TLS-проверок — 32. Допускается не более 8 разных узлов, 16 разных портов, 8 уникальных адресов на узел и 32 одновременных TCP/TLS-проверок. `--timeout` принимает значение больше 0 и не больше 60 секунд; `--concurrency` — от 1 до 32. Слот параллелизма занят до окончания TLS и закрытия сокета. Если resolver вернул больше 8 адресов, отчёт помечает усечение.

Ошибки параметров обнаруживаются до сетевых запросов. Текстовый отчёт показывает адреса, статусы и время каждой проверки. Результаты сохраняют порядок: узлы в порядке ввода, адреса в порядке ответа resolver, порты в порядке ввода.

Для IPv6 поддерживаются зоны интерфейсов в числовом или именованном виде, например `fe80::1%3` или `fe80::1%en0`. Зона, возвращённая системным resolver, сохраняется в адресе отчёта. При TCP-подключении она передаётся как числовой `scope_id`, без повторного разрешения имени.

## Добровольная TLS-проверка

`--tls` включает TLS для **каждого** переданного порта после успешного TCP-подключения. Номер порта ничего не включает автоматически: без флага даже порт 443 проверяется только через TCP. На обычном TCP-сервисе TLS может завершиться ошибкой или тайм-аутом. Поддерживается прямой TLS; STARTTLS и HTTP не выполняются.

Рукопожатие использует уже подключённый числовой адрес и тот же сокет. Повторных DNS-запросов, вторых TCP-подключений, обхода проверки сертификата и отправки прикладных данных нет. Исходное имя узла передаётся как SNI и имя проверки сертификата. Для IP проверяется IP SAN сертификата, SNI не отправляется; зона IPv6 исключается из имени проверки.

Доверие и безопасные настройки протокола задаёт стандартный Python [`ssl.create_default_context()`](https://docs.python.org/3/library/ssl.html#ssl.create_default_context): обязательны проверка цепочки, срока действия и имени сертификата. Используются стандартные источники доверия Python/OpenSSL, включая `SSL_CERT_FILE` и `SSL_CERT_DIR`, если они заданы пользователем. На macOS они зависят от поставки Python и не обязательно совпадают с Keychain; при отсутствии нужного CA будет `certificate_error`. RouteScope не устанавливает CA и не загружает сертификаты из интернета. Флага отключения проверки нет.

Отчёт показывает TLS-версию, согласованный шифр, начало и конец действия проверенного серверного сертификата в UTC и время рукопожатия. Загрузка локального хранилища доверия не входит в это время. `--timeout` отдельно ограничивает всё рукопожатие, а не каждое чтение. При ошибке сертификат повторно без проверки не запрашивается, его поля остаются `null`. После проверки соединение закрывается; ожидания TLS shutdown нет.

## Статусы и коды завершения

DNS имеет статус `resolved`, `literal`, `error` или `timeout`. Статус `literal` означает, что вход уже был числовым IP-адресом и запрос resolver не выполнялся. TCP имеет статус `connected`, `refused`, `timeout`, `unreachable` или `error`.

Общий статус `ok` означает, что каждый узел дал хотя бы один адрес и все TCP-проверки завершились подключением. `partial` означает, что было хотя бы одно подключение и хотя бы одна ошибка DNS или TCP. `failed` означает, что подключений не было. Код завершения: `0` для `ok`, `1` для `partial` и `failed`, `2` для ошибки использования, `130` при Ctrl+C. Ошибки CLI и сообщение о прерывании идут в stderr.

При `--tls` успехом считается полная проверка TCP + проверенный TLS. TLS имеет статусы `verified`, `certificate_error` (в том числе неверное имя, недоверенная цепочка или истёкший сертификат), `handshake_error` (другая ошибка рукопожатия/транспорта), `timeout` или `skipped` (TCP не подключился). TCP при TLS-ошибке сохраняет `connected`. Общий статус — `ok`, если все проверки полностью успешны и нет ошибок DNS; `partial`, если есть хотя бы одна полная успешная проверка и хотя бы одна ошибка DNS/TCP/TLS; `failed`, если полных успехов нет. Даже если все TCP-соединения установлены, все неудачные TLS дают `failed` и код `1`. Сбой одной проверки не отменяет остальные. Ctrl+C закрывает активные сокеты, даёт код `130` и сообщение в stderr, без незавершённого JSON в stdout.

Неудачное TCP-подключение к одному адресу не доказывает, что весь узел недоступен: вывод отражает только выполненные проверки.

## JSON

В режиме `--format json` stdout содержит один JSON-документ без дополнительных сообщений. Структура версии 2 (прежние поля сохранены; версия повышена из-за нового смысла общего статуса при TLS):

```json
{
  "schema_version": 2,
  "parameters": {
    "hosts": ["127.0.0.1"],
    "ports": [8000],
    "family": "both",
    "timeout_s": 3.0,
    "concurrency": 32,
    "format": "json",
    "tls": false
  },
  "status": "failed",
  "duration_ms": 1.2,
  "targets": [
    {
      "host": "127.0.0.1",
      "dns": {
        "status": "literal",
        "duration_ms": 0.1,
        "addresses": [{"address": "127.0.0.1", "family": "ipv4"}],
        "error": null,
        "truncated": false
      },
      "tcp": [{
        "address": "127.0.0.1",
        "family": "ipv4",
        "port": 8000,
        "status": "refused",
        "duration_ms": 1.0,
        "error": "connection refused",
        "tls": null
      }]
    }
  ],
  "summary": {
    "connected": 0,
    "refused": 1,
    "timeout": 0,
    "unreachable": 0,
    "error": 0,
    "dns_errors": 0,
    "tcp_checks": 1
  }
}
```

Все длительности результатов выражены в миллисекундах (`*_ms`), тайм-аут настройки — в секундах (`timeout_s`). Сводка `dns_errors` включает DNS-ошибки и тайм-ауты. Поле `error` равно `null`, если ошибки нет. При несовместимом изменении структуры номер `schema_version` будет увеличен.

При `parameters.tls: true` каждый элемент `targets[].tcp[]` дополнительно содержит объект `tls`, например:

```json
{
  "status": "verified",
  "duration_ms": 12.5,
  "version": "TLSv1.3",
  "cipher": "TLS_AES_256_GCM_SHA384",
  "certificate_not_before": "2020-01-01T00:00:00Z",
  "certificate_not_after": "2040-01-01T00:00:00Z",
  "error": null,
  "verify_code": null
}
```

`verify_code` содержит код OpenSSL при `certificate_error`; текст `error` и конкретный код могут зависеть от версии OpenSSL. При TLS-неуспехе версия, шифр и сроки сертификата равны `null`. При `skipped` длительность равна `0`; без `--tls` объект равен `null`. Поле TCP `duration_ms` по-прежнему измеряет только TCP-подключение.

При включённом TLS сводка сохраняет прежние TCP/DNS-счётчики и добавляет `tls_verified`, `tls_certificate_error`, `tls_handshake_error`, `tls_timeout`, `tls_skipped`, `tls_checks`. Последний считает реально начатые TLS-проверки (TCP `connected`), исключая `skipped`. При DNS-ошибке TCP/TLS-результатов для узла нет; ошибка учитывается в `dns_errors`. Без `--tls` дополнительных TLS-счётчиков нет.

## Архитектура

- `cli.py` проверяет аргументы и назначает код завершения.
- `models.py` задаёт типизированные результаты и JSON-поля.
- `dns.py` обращается к системному resolver и удаляет повторяющиеся адреса.
- `tcp.py` подключается напрямую к числовым адресам и закрывает сокеты.
- `tls.py` проводит проверенное рукопожатие через `ssl.MemoryBIO` на переданном сокете; не подключается и не разрешает имён.
- `diagnose.py` координирует проверки и ограничивает параллелизм.
- `report.py` создаёт текстовый отчёт или JSON.

Владелец сокета — `tcp.py`: он закрывает его в `finally` при успехе, ошибке и отмене, включая TLS. Оркестратор держит общий предел параллелизма на всю цепочку TCP/TLS. Следующий возможный модуль развития — отдельная HTTP-проверка поверх проверенного TLS с собственной моделью результата; в текущую версию она не входит и требует отдельного согласования.

## Ограничения

DNS выполняется через системный `getaddrinfo`. Измеренное время включает поведение локального resolver и кэша; оно не является точным временем DNS-пакета. Этот API не предоставляет TTL или адрес использованного DNS-сервера. При тайм-ауте RouteScope перестаёт ждать ответ, но уже запущенная системная операция может продолжить работу в фоновом потоке. Завершение процесса также может задержаться в ожидании этого потока: `--timeout` ограничивает ожидание отдельной проверки, а не общее время работы команды.

RouteScope не сканирует диапазоны портов или подсети, не использует raw sockets и не выполняет HTTP-проверки. Нет STARTTLS, клиентских сертификатов (mTLS), аудита всех шифров/версий и отдельного запроса OCSP/CRL. TLS использует безопасные настройки текущего Python/OpenSSL; результат относится только к одной согласованной сессии. Результат TCP относится к конкретному адресу и порту в момент проверки.

## Тесты

Для разработки установите пакет в редактируемом режиме:

```bash
python -m pip install -e .
python -W error scripts/run_tests.py
```

Тесты не требуют публичного интернета. Сквозные проверки поднимают локальный TCP-сервер на `127.0.0.1` и используют `localhost` для системного разрешения имени; отдельно проверяется реальное соединение с `::1`. Для запуска тестов нужен работающий IPv6 loopback. Остальные сетевые исходы, включая отказ TCP, воспроизводятся управляемыми подменами: закрытый порт может быть занят другим процессом, а порт без `listen` на разных ОС может дать отказ или тайм-аут. Обязательны оба способа запуска; отсутствие установленной команды `routescope` считается ошибкой. В процессе тестов `run_tests.py` блокирует DNS и TCP за пределами loopback; отдельные процессы CLI получают только `localhost` и числовые loopback-адреса. Предупреждения Python считаются ошибками.

TLS-тесты используют локальный сервер и сохранённые [тестовые сертификаты](tests/fixtures/tls/README.md), действующие в 2020–2040 годах. CA доверяется только тестовым контекстом или дочерним CLI, системное доверие не меняется. Проверяются TLS 1.2/1.3, IPv4/IPv6, SNI/проверка IP, одна TCP-сессия без повторного resolver, недоверенный CA, неверное имя, ошибка рукопожатия, тайм-аут, частичный успех, общий параллелизм и закрытие при отмене/Ctrl+C. OpenSSL CLI и сторонняя библиотека для генерации сертификатов при запуске тестов не нужны.

## Сборка и CI

```bash
python -m pip install build
python -m build
python scripts/check_install.py
```

`build` — инструмент разработки; у RouteScope нет зависимостей времени выполнения. Сначала собирается исходный архив (sdist), затем wheel из этого архива. Проверка установки создаёт временное чистое окружение, устанавливает wheel с `--no-index --no-deps`, выполняет `pip check` и запускает тесты вне рабочего каталога проекта без `PYTHONPATH`. Проверяется импорт именно установленного пакета, оба способа запуска, системное разрешение `localhost`, TCP и текстовый/JSON-отчёты.

[GitHub Actions](https://github.com/engineer5330/RouteScope/actions/workflows/ci.yml) выполняет эти шаги на `ubuntu-latest` и `macos-latest` с Python 3.11, 3.12 и 3.13 при отправке в `main`, для pull request и вручную. Интернет используется для получения инструментов сборки и её зависимостей; установка wheel и тесты не требуют публичных узлов. Windows, другие версии Python и все возможные конфигурации resolver этой матрицей не проверяются. Фактические версии ОС и архитектуры доступны в журнале каждого запуска CI.
