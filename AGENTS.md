# RouteScope: правила работы в репозитории

## Цель и границы текущего выпуска

RouteScope — CLI для диагностики подключений на macOS и Linux (Python 3.11+). Третий этап расширяет готовый DNS/TCP MVP: явные узлы и TCP-порты → системное разрешение имени → подключение к полученным числовым адресам → добровольный TLS на том же сокете → текстовый или JSON-отчёт. Поддерживать `routescope` и `python -m routescope`.

TLS разрешён только явным `--tls` на всех переданных портах независимо от их номеров. Не добавлять сервер, БД, Docker, облачные сервисы, систему плагинов, HTTP, STARTTLS, ICMP, traceroute или историю запусков. Оставить небольшие явные границы между модулями, чтобы их можно было добавить позднее. Новые обязательные runtime-зависимости не нужны.

## Рабочий порядок

1. Перед изменением прочитать текущие файлы, `README.md`, `pyproject.toml` и тесты, если они есть; проверить `git status` и сохранить чужие изменения.
2. Сначала зафиксировать наблюдаемый контракт CLI и моделей, затем провести один сквозной сценарий через CLI, DNS, TCP, добровольный TLS и отчёт.
3. Разделять ввод/валидацию, оркестрацию, DNS, TCP, TLS и форматирование. Использовать типизированные модели результатов; исключения переводить в понятные статусы на границе проверки.
4. Добавлять минимальные зависимости только с объяснимой пользой. Предпочитать стандартную библиотеку и `asyncio`.
5. Проверять изменения локальными тестами без публичного интернета. Если тест нельзя воспроизвести надёжно, подменить resolver или соединение контролируемым объектом.
6. Обновлять README вместе с изменением интерфейса, JSON-схемы или ограничений. По завершении сообщать, что реально проверено и что не удалось проверить.

## Контракт MVP

- Команда: `routescope diagnose HOST [HOST ...] --ports 80,443 [--family ipv4|ipv6|both] [--timeout SECONDS] [--concurrency N] [--format text|json] [--tls]`.
- Проверять все параметры до сетевых операций. Порты — уникальные целые от 1 до 65535; повторяющиеся узлы и порты обрабатывать предсказуемо и документировать порядок.
- Пределы: не более 8 узлов, 16 портов, 8 адресов на узел и 32 одновременных TCP/TLS-проверок; тайм-аут по умолчанию 3 секунды отдельно на DNS, TCP и всё TLS-рукопожатие. Слот параллелизма держать до окончания TLS и закрытия сокета. Изменять пределы вместе с тестами и README. При усечении списка адресов явно отмечать это в отчёте.
- Для имени использовать асинхронный вызов системного resolver, выбрать запрошенные семейства, удалить дубли с сохранением порядка. Числовой IP не отправлять в resolver. Измерение называть временем системного разрешения; не приписывать ему TTL, DNS-сервер или сетевую задержку DNS-пакетов. Тайм-аут ожидания системного resolver не гарантирует остановку уже запущенной системной операции.
- TCP подключать только к числовому адресу с явным семейством, не вызывая повторного разрешения имени. Ограничить общую параллельность. Различать `connected`, `refused`, `timeout`, `unreachable`, `error`; хранить длительность в миллисекундах. Закрывать сокет при любом исходе, включая отмену. Сбой одного адреса не отменяет остальные.
- TLS выполняется только после TCP `connected`, на том же сокете без второго подключения или разрешения имени. Использовать `ssl.create_default_context()` и стандартные источники доверия Python/OpenSSL (на macOS не обещать совпадения с Keychain). Для имени использовать исходный узел как SNI и имя проверки; для IP проверять IP SAN без SNI, исключая зону IPv6. Не добавлять обход проверки сертификата. Различать `verified`, `certificate_error`, `handshake_error`, `timeout`, `skipped` (TCP не подключился); без флага `tls: null`. Показать версию, шифр, сроки сертификата в UTC и время рукопожатия. Не извлекать сертификат повторным небезопасным соединением при ошибке.
- Сохранять порядок целей, адресов и портов в результатах независимо от порядка завершения задач. Общий статус: `ok`, если каждый узел дал адреса и все TCP-проверки успешны; `partial`, если есть хотя бы одно успешное подключение и хотя бы одна ошибка DNS или TCP; `failed`, если успешных подключений нет. В сводке показывать количество проверок каждого исхода и число ошибок DNS.
- При `--tls` успешна только полная цепочка TCP + TLS `verified`: `ok`, если все цепочки успешны и нет ошибок DNS; `partial`, если есть полный успех и ошибка DNS/TCP/TLS; `failed`, если полных успехов нет. TCP-статус и длительность при ошибке TLS сохраняются. Добавлять отдельные TLS-счётчики; `tls_checks` исключает `skipped`. Не менять поведение диагностики без флага.
- Коды завершения: `0` — все проверки успешны, `1` — диагностика завершена с частичным или полным неуспехом, `2` — ошибка аргументов/использования, `130` — прерывание Ctrl+C. Ошибки использования и служебные сообщения направлять в stderr.
- В режиме JSON stdout содержит ровно один JSON-документ: `schema_version`, параметры запуска, результаты по целям/адресам/портам, статусы, длительности с суффиксом `_ms`, сводку. Текущая версия схемы — `2` (новый смысл общего статуса с TLS); поля версии `1` сохранены. Менять версию при несовместимом изменении формата. Не смешивать диагностические сообщения с JSON в stdout.

## Безопасность и точность

Проверять только переданные пользователем узлы и порты. Не сканировать диапазоны, подсети и соседние устройства. Не требовать root, не использовать raw sockets, не отправлять прикладные данные после TCP-подключения и не запускать shell-команды из пользовательского ввода. Не добавлять телеметрию или автоматическую отправку отчётов. Формулировать выводы как наблюдения конкретных проверок, а не как доказательство доступности или недоступности всего узла. README должен напоминать о диагностике собственных систем или систем с разрешения владельца.

## Проверка готовности

- Установка по `pyproject.toml` и оба способа запуска работают.
- Локальная сквозная проверка проходит без публичного интернета.
- Тесты покрывают валидацию, семейства и дедупликацию DNS, DNS-ошибку/тайм-аут, успешное TCP-соединение с локальным сервером, отказ/тайм-аут/отмену, предел параллелизма, частичный успех, JSON и коды завершения.
- TLS-тесты автономны: локальный сервер, тестовый CA/сертификат, TLS 1.2/1.3, SNI/IP, недоверенный CA, несовпадение имени, ошибка рукопожатия, тайм-аут, отмена/Ctrl+C, одна TCP-сессия, общий параллелизм и частичный успех. Тестовый CA не устанавливать в системное доверие, ключи использовать только в тестах. Срок тестовых сертификатов — 2020–2040 годы; fixture должен попасть в sdist.
- Перед публикацией проверять сборку sdist/wheel и чистую установку; после отправки без force push дождаться успешного CI macOS/Linux × Python 3.11/3.12/3.13.
- README описывает установку и запуск на macOS/Linux, команды, поля JSON, коды завершения, пределы и ограничения системного resolver.
- В репозитории зафиксированы архитектурные границы и следующий модуль развития.
